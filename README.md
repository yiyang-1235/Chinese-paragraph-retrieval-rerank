# 中文段落检索与重排序

**关键词**：信息检索 · BM25 · 语义向量检索 · 交叉编码器重排序 · RAG · FAISS · BGE

---

## 项目背景

在 RAG（检索增强生成）和搜索类 Agent 系统中，大语言模型的回答质量直接依赖于「把最相关的段落找回来」这一步。

传统做法（BM25）只看词形重叠：用户查「怎么退火车票」，文档写的是「退改签规则」，BM25 会漏掉这条正确段落。

神经语义检索（BGE 双编码器）把查询和段落各自编成向量，再算余弦相似度，能捕捉词形不同但语义相近的匹配。

但双编码器独立编码两段文本，缺少词级别的交互。交叉编码器（重排序）把「查询 + 段落」拼在一起过模型，精度更高，但只能用在少量候选上。

本项目在 **T2Retrieval**（中文段落检索标准测试集，800 条 dev 查询，约 2.3M 候选段落）上复现并对比三个版本，量化说明每一步的收益。

---

## 系统架构

```
查询
 │
 ├── BM25（jieba 分词 + 倒排索引）──────────────────→ top-100 → 评测
 │
 └── BGE-small-zh（FAISS 向量检索）────────────────→ top-100 → 评测
                                 │
                                 └── BGE-reranker-base（交叉编码器）→ top-100 → 评测
```

## 三版对比（实验结果填入）

| 方法 | Recall@1 | Recall@5 | Recall@10 | NDCG@10 | MRR@10 |
|------|----------|----------|-----------|---------|--------|
| 版本一：BM25 | 0.4312 | 0.7652 | 0.8320 | 0.3375 | 0.5646 |
| 版本二：BGE 向量检索 | 0.5810 | 0.8988 | 0.9453 | 0.5089 | 0.7195 |
| 版本三：BGE + 重排序 | **0.6235** | **0.9352** | **0.9595** | **0.5591** | **0.7568** |

数据集：T2Ranking（SIGIR 2023），500 条 dev 查询，50354 条候选段落，多级相关性标注（1-3分）

## 错误分析

实验脚本末尾自动输出两类典型失败案例：

- **BM25 漏检、BGE 命中**：查询与段落词形差异大，语义匹配有优势（例：「打疫苗有副作用吗」 vs「接种后的不良反应」）
- **BGE 漏检、BM25 命中**：查询包含专有词汇，词形完全相同，向量模型反而泛化过度

## 运行方式

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 下载并预处理数据（约 20 分钟，只需运行一次）
python data/prepare_data.py

# 3. 运行三版实验，输出对比表
python run_experiment.py
```

FAISS 索引会在首次运行后保存至 `results/faiss_index/`，后续实验直接复用，无需重新编码语料库。

## 技术栈

| 模块 | 库 / 模型 |
|------|----------|
| 中文分词 | jieba |
| BM25 | rank_bm25 |
| 语义编码 | BAAI/bge-small-zh-v1.5（sentence-transformers） |
| 向量索引 | FAISS（faiss-cpu） |
| 重排序 | BAAI/bge-reranker-base（CrossEncoder） |
| 评测指标 | 自实现 Recall@K、NDCG@K、MRR@K |
